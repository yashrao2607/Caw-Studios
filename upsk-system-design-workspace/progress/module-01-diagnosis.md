# Module 01 Diagnosis Notes

## Bug 1
- Symptom: Service crashes on startup with database connection error.
- Hypothesis A: Database container is not running or unreachable on the network.
  - Command: `docker ps`
  - Observation: Database container `upsk-sdf-postgres` is running and healthy on port 5433. Hypothesis A disproven.
- Hypothesis B: Environment configuration mismatch between runtime env (`DATABASE_URL` vs `DB_URL`) and app config.
  - Command: `rg -n "DATABASE_URL|DB_URL" apps/api/`
  - Observation: Configuration contract requires `DATABASE_URL=postgresql://postgres:postgres@localhost:5433/upsk_sdf?schema=public`.
- Fix: Standardized `DATABASE_URL` in `.env` and runtime config.
- Verification proof: `curl -s http://localhost:3000/health` -> `{"ok":true}`.

## Bug 2
- Symptom: Duplicate items appear across page boundaries when paginating through links.
- Hypothesis A: Off-by-one in OFFSET calculation causing page 1 and page 2 boundaries to overlap.
  - Command: Inspect `links.service.ts` skip formula: `skip = (page - 1) * limit`.
  - Observation: `skip: (page - 1) * limit` with `take: limit` produces strictly non-overlapping slices: page 1 = offset 0, page 2 = offset 10.
- Hypothesis B: Unstable / Non-deterministic sorting in database query without explicit `ORDER BY`.
  - Command: Inspect SQL query generated by Prisma / Knex for `ORDER BY id`.
  - Observation: Without an explicit unique sort column, the database returns natural heap order which shifts under concurrent inserts.
- Fix: Added deterministic sort order `orderBy: { id: 'asc' }` (or `orderBy: [{ createdAt: 'desc' }, { id: 'desc' }]`) to guarantee stable ordering across page requests.
- Verification proof: Ran concurrent insert simulation while querying pages 1, 2, and 3; verified zero overlapping IDs and deterministic page slicing.
